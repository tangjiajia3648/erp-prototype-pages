# ERP原型开发

## 适用场景

- 将已确认需求实现为Vue PC端原型、交互演示或页面优化。
- 创建预算、合同、订单、发票、回款等新建、编辑、详情和审批页面。
- 补充Mock数据、状态切换、表单联动、列表操作及响应式展示。

## 核心规则

- 先检查项目技术栈、路由、组件库、现有母版和工作区改动，再开始实现。
- 优先复用现有布局、组件、变量和交互，不为单页重复造一套体系。
- 原型字段以正式代码和确认需求为准，不删减原字段；未确认内容标为原型假设。
- 页面结构区分标题、一级模块、二级模块、正文、右侧工作台和底部操作。
- 新建与编辑复用结构；详情和审批复用内容顺序，审批只增加审批信息和操作。
- 可编辑、只读带出、自动计算、链接和状态必须有不同组件语义与视觉。
- Mock数据覆盖正常、空、异常、审批中、完成等关键状态，并保持单据关联一致。
- 业务联动集中管理，不把同一枚举和计算规则复制到多个页面。
- 所有商品明细保留SKU编码；金额、日期、天数和状态使用统一格式。
- 响应式布局优先保证可读性；右侧工作台可收起，窄屏不挤压正文。
- 改动后运行构建和必要交互检查；多份原型源存在时按项目约定同步并校验一致性。

## 工作流程

1. 读取需求、相关业务 Skill、交互 Skill、项目说明和现有代码。
2. 盘点页面状态、字段、交互、复用组件、Mock场景和验收点。
3. 先沿用母版搭建结构，再实现业务差异和联动。
4. 实现错误提示、空状态、只读状态、禁用条件、跳转和反馈。
5. 检查不同分辨率、长文本、宽表格和工作台收缩。
6. 构建项目并验证关键入口、切换、提交和展示结果。
7. 报告修改范围、验证结果、原型假设和仍待确认的业务规则。

## 输出要求

- 交付可运行源文件，不只提供静态截图。
- 说明实现了哪些页面、状态、联动和异常场景。
- 提供可点击的本地文件路径或预览入口，以及构建验证结果。
- 对产品经理用页面结果和交互效果解释，不要求理解代码细节。

## 禁止事项

- 不把Mock接口、演示状态提醒或示例人员金额当成正式生产逻辑。
- 不复制正式系统的登录、权限、菜单和无关业务页面到独立原型。
- 不覆盖用户已有改动，不用破坏性命令清理工作区。
- 不只验证编译；对关键交互和视觉问题应进行实际页面检查。
