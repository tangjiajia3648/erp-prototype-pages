# 发票与财务业务

## 适用场景

- 进项发票、销项发票、红字冲销、蓝字发票和发票匹配需求。
- 发票登记、认证、做账、核销及财务系统推送状态设计。
- 金蝶、浪潮或其他财务接口的字段映射、重试和对账方案。

## 核心规则

- 发票必须可追溯到开票主体、交易对象、合同、订单、商品／费用及原始凭证。
- 业务状态、做账状态和接口推送状态分开管理，不能用一个状态代替全部过程。
- 含税金额、不含税金额和税额口径保持一致；允许的舍入差异必须明确。
- 发票匹配支持一对一、一对多、多对一、部分匹配和剩余金额，匹配结果要可解释、可撤销、可审计。
- 红字发票必须关联被冲销的蓝字发票，记录冲销范围、原因和剩余可冲金额；不得覆盖原票。
- 重复票号、重复代码、主体不一致、税率异常、金额超限和已匹配冲突必须进入异常处理。
- 金蝶和浪潮视为独立接口适配器，分别确认字段、枚举、凭证规则和回执，不能假定规则相同。
- 外部推送必须有业务唯一键或幂等键；保存请求、响应、次数、时间和最终结果。
- 接口失败可重试但不得重复生成凭证；超过规则阈值转人工处理。
- 正式代码当前只有占位能力时，只能输出建模建议与待确认清单，不能声称已有规则已落地。

## 工作流程

1. 确认发票方向、票种、来源、主体、税率和业务单据。
2. 梳理登记、校验、匹配、审核、做账、推送、回执和冲销状态。
3. 定义金额口径、匹配优先级、可拆分范围和差异处理。
4. 分别设计金蝶、浪潮字段映射、幂等、重试、回执和对账。
5. 补充红蓝字、作废、重复、跨期、接口失败和人工调整场景。
6. 输出已确认规则、建议规则及待财务确认项。

## 输出要求

- 包含业务流程、状态机、匹配规则、金额校验、接口规则、异常队列和审计信息。
- 接口说明使用“来源字段／目标字段／转换规则／必填／失败处理／回执字段”。
- 匹配结果展示匹配依据、匹配金额、剩余金额、置信或校验结果及人工操作。
- 财务口径未确认时明确提出问题，不代替财务人员决策。

## 禁止事项

- 不假定金蝶与浪潮字段、状态和凭证规则一致。
- 不自动修改已做账或已推送成功的数据而不留下反向记录。
- 不用删除原记录的方式处理红冲、作废和反做账。
- 不把接口请求成功等同于财务系统已入账，必须以有效回执为准。
