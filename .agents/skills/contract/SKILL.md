# 合同与预算业务

## 适用场景

- 预算单、采购合同、销售合同及关联订单的需求分析和页面设计。
- 合同生成、变更、审批、用印、附件和后续任务规则梳理。
- 分析商品、金额、责任人和关联单据之间的同步与影响。

## 核心规则

- 预算是采销计划和收益测算依据；计算结果只读，计算口径必须可追溯到商品明细。
- 商品明细是核心数据，预算、合同、订单相关明细必须保留SKU编码。
- 业务类型可能有一级和二级分类；下游规则以实际业务子类型判断，页面展示完整路径。
- 合同应记录来源预算或来源订单；关联编号可追溯，来源数据要区分只读带出与合同可编辑内容。
- 采购合同和销售合同共享骨架，但不得删减各自正式字段。
- 创建采购合同时采购责任人和业务单元由来源带出只读；销售合同对应销售责任人和业务单元同理。
- 合同金额与结算集中管理税率、含税额、不含税额、税额、账期、日期和结算条款。
- 交付履约与用印分别成组；系统生成合同仍要保留适用的印章和用印要求。
- 合同文件记录正文、模板、版本、印章配置及变更识别；附件与说明保持同一业务模块。
- 合同变更必须说明变更前后值、影响单据、是否重算金额、是否重新审批及历史版本保留方式。
- 上游商品、数量、价格或税率变化时，必须分析合同、订单、毛利、发票和回款的连锁影响。
- 详情不混入履约档案系统才应管理的归档信息；仅在有实际后续任务时展示后续任务。
- 审批进度、审批意见和评论分开；退回、驳回、并行、抄送和关注保留各自语义。

## 工作流程

1. 识别业务类型、单据阶段、来源单据和采购／销售方向。
2. 梳理预算、合同、订单的关联关系和字段来源。
3. 明确金额、商品、责任人、结算、交付、用印和文件规则。
4. 建立创建、提交、审批、生效、变更、作废及后续任务状态流。
5. 做变更影响分析，覆盖下游单据、接口、历史版本和在途审批。
6. 输出业务方案；规则未在资料或正式代码中确认时列为待确认。

## 输出要求

- 标明页面或流程属于预算、采购合同、销售合同或订单。
- 输出单据关系、字段来源、同步时机、可编辑范围、状态和变更影响。
- 变更方案至少包含原值、新值、影响对象、处理动作、审批要求和审计记录。
- 页面建议沿用预算／合同母版，并说明与母版不同的业务原因。

## 禁止事项

- 不把原型示例金额、公司、人员、日期和状态数量当成业务规则。
- 不擅自合并名称相似但业务含义未确认的字段。
- 不允许变更覆盖历史版本或破坏已生效单据的追溯关系。
- 不默认预算、合同、订单只能按单一路径创建；必须以业务类型和正式入口为准。
