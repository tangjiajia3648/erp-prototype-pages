# ERP PC端交互设计

## 适用场景

- 新建、编辑、详情、审批、列表和工作台页面设计或优化。
- 处理字段多、表格宽、状态复杂、关联单据多的企业软件页面。
- 统一预算、合同、订单等页面的信息层级、操作入口和响应式规则。

## 核心规则

- 同一单据的新建、编辑、详情和审批保持字段名称、顺序、单位和分组一致。
- 可编辑控件、自动带出只读信息和计算结果必须有清楚的视觉差异。
- 表单宽屏优先一行四个字段；空间不足依次降为三列、两列、一列，不压缩文字到不可读。
- 详情统一“标签在上、内容在下”，减少输入框式灰底和重复卡片。
- 一级模块使用明确编号和标题；二级模块弱化一级视觉，避免父子标题同名。
- 标题区用于识别单据、状态和少量核心指标；正文不再复制同一套摘要。
- 列表先保证识别、筛选、状态和高频操作；长表格固定关键列，金额和数量对齐。
- 筛选区区分高频条件与高级条件，保留已选条件并支持清空和恢复。
- 状态用文字加颜色表达，颜色只作辅助；同一状态全系统保持同一语义。
- 主操作明确且唯一，次要操作收入口；新建编辑操作放底部，审批操作固定底部并保持紧凑。
- 供应商、客户、单据编号等可跳转对象使用链接样式，并保持返回上下文。
- 右侧工作台用于指标、导航和提醒，可收起；窄屏自动隐藏，不挤压正文。
- 空数据、加载、失败、只读、禁用和无权限必须分别表达。

## 工作流程

1. 确认页面任务、用户角色、页面状态及最高频操作。
2. 依据业务流程组织信息架构，再安排字段和组件。
3. 区分编辑字段、只读字段、计算结果、风险提示和关联入口。
4. 设计列表、筛选、状态、跳转、反馈、错误定位和响应式行为。
5. 对照同类母版检查一致性、信息密度、重复内容和操作成本。
6. 说明交互规则、异常表现和验收要点，必要时再进入原型实现。

## 输出要求

- 输出页面目标、结构、字段分组、操作规则、状态反馈和响应式规则。
- 优化建议说明“现状问题／调整方式／用户收益／业务影响”。
- 交互方案标明默认状态、触发方式、结果反馈和异常处理。
- 评审页面时区分必须修改、建议优化和业务待确认。

## 禁止事项

- 不为追求视觉整洁删除业务字段、状态或审计信息。
- 不混用横向、纵向阅读方式，不用大量边框制造层级。
- 不让只读字段保留下拉箭头、输入边框等可编辑暗示。
- 不把详情摘要、正文指标和右侧指标重复展示。
- 不用弹窗承载可以在当前上下文完成的简单操作。
